== Reactive classes

Four common classes used throughout the framework are {url-javadoc}{common-reactive}/is/codion/common/reactive/event/Event.html[Event], {url-javadoc}{common-reactive}/is/codion/common/reactive/signal/Signal.html[Signal], {url-javadoc}{common-reactive}/is/codion/common/reactive/state/State.html[State] and {url-javadoc}{common-reactive}/is/codion/common/reactive/value/Value.html[Value], observed via {url-javadoc}{common-reactive}/is/codion/common/reactive/sensor/Sensor.html[Sensor], {url-javadoc}{common-reactive}/is/codion/common/reactive/observer/Observer.html[Observer] and {url-javadoc}{common-reactive}/is/codion/common/reactive/state/ObservableState.html[ObservableState].

NOTE: Not all available methods are included in the diagrams below, see javadocs for details.

[#_event]
=== Events and signals

-------------------------------------------

Two kinds of synchronous events are used throughout the framework:

* An {url-javadoc}{common-reactive}/is/codion/common/reactive/event/Event.html[Event] carries no data.
It is triggered by calling *run*, which notifies its listeners, {url-jdk-javadoc}/java.base/java/lang/Runnable.html[Runnable] instances added via its {url-javadoc}{common-reactive}/is/codion/common/reactive/sensor/Sensor.html[Sensor].
* A {url-javadoc}{common-reactive}/is/codion/common/reactive/signal/Signal.html[Signal] carries data.
It is triggered by calling *accept*, which notifies its listeners and its consumers, {url-jdk-javadoc}/java.base/java/util/function/Consumer.html[Consumer] instances receiving the data, added via its {url-javadoc}{common-reactive}/is/codion/common/reactive/observer/Observer.html[Observer].

An Observer is a Sensor as well, so anything only interested in the fact that something happened can listen to an event, a signal, a value or a state alike.
Listeners and consumers are notified in the order they were added.

Classes typically expose the sensors of their events and the observers of their signals via public accessors.
A sensor or an observer can not trigger its event or signal and can be safely passed around.

Events and signals are instantiated via the factory methods {url-javadoc}{common-reactive}/is/codion/common/reactive/event/Event.html#event()[Event.event()] and {url-javadoc}{common-reactive}/is/codion/common/reactive/signal/Signal.html#signal()[Signal.signal()].

[#_weak_listeners]
== Weak listeners

Every sensor and observer accepts listeners via weak references — *addWeakListener()*, and on an observer *addWeakConsumer()* — which do not prevent the listener from being garbage collected.
A short-lived component observing a long-lived model should use a weak listener (or remove its listeners when discarded), otherwise the model keeps the discarded component reachable forever.
Dead references are cleaned up automatically; the caller must simply ensure something holds a strong reference to the listener for as long as it should stay active.

[#_reactive_threading]
== Threading

Listener management — adding and removing — is thread-safe on all reactive classes.
Mutation and notification are *not*: *set()*, *run()* and *accept()* are designed to be called from a single thread, the UI thread in a typical application.
A background thread with a result for a value hands it to the UI thread first — in Swing via *SwingUtilities.invokeLater* or, better, a *ProgressWorker* whose *onResult* already runs there.

Listeners are notified synchronously, in the order they were added, and an exception thrown by a listener prevents the remaining ones from being notified — listeners performing risky work handle their own exceptions.
