== Roots and children

The roots, and the children via each foreign key, can be configured with a condition, the `Select` they are selected with, its where condition already set, and a comparator. A roots condition replaces the default one, while a children condition is combined with the foreign key condition, which the tree owns, so it can not be left out. The children condition also applies when finding which nodes have children, while a limit or an offset leaves nodes out.

----

Siblings of different entity types are ordered by type, in the order their foreign keys were configured. Siblings of one type are ordered by the first of:

. the comparator of the roots, or of the foreign key;
. the order by of their select, keeping the query order;
. the comparator of the tree, specified via the builder's `comparator()`;
. the comparator of the entity type.

== Leaves

Whether a node is a leaf is decided when its parent is loaded, along with its siblings, so a node never expanded shows whether it has children:

* a node of an entity type no configured foreign key references is always a leaf, without a query;
* for the others, a single query per foreign key referencing their type finds which of the siblings are referenced.

The leaf detection can be replaced via the builder's `leaf()` or `leaves()`, for example with a domain attribute stating whether an entity has children.

== Updates

The model updates when refreshed, `nodes().refresh(path)` reloading a node and the loaded nodes below it exactly, while `nodes().add()`, `replace()` and `remove()` apply edits in memory.
