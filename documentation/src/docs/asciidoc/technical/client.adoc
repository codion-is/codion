== Features

* Lightweight client with a simple synchronous event model
* Provides a {url-help}/client.html#_keyboard_shortcuts[practically mouse free] user experience
* Graceful handling of network outages and server restarts
* Clear separation between model and UI
* Easy to use load testing harness provided for applications
* UI data bindings for most common components provided by the framework
* Implementing data bindings for new components is made simple with building blocks provided by the framework
* The default UI layout is a simple and intuitive “waterfall” master-detail view
* Extensive {url-help}/client.html#_searching[searching] and filtering capabilities
* Flexible keyboard-centric UI based on tab and split panes, detachable panels and toolbars
* Detailed logging of client actions

== Configuration

The framework is configured via configuration values, static {url-javadoc}{common-utilities}/is/codion/common/utilities/property/PropertyValue.html[PropertyValue] constants found in the classes they configure, each with a default value, specified in its javadoc along with the value type. The manual refers to a configuration value by its constant, linking to the javadoc.

A configuration value typically provides the default for a setting which can also be specified for an individual model or component, via a builder or otherwise.

=== In code

Configuration values are usually set in code, in the application main method.

[source,java,indent=0]
----
include::{dir-source}/is/codion/demos/chinook/ui/ChinookAppPanel.java[tags=configuration]
----

NOTE: Most configuration values are read when the class they configure is loaded or instantiated, they must be set before that happens, which is why this is done first thing in the main method.

=== System properties

Each configuration value is backed by a system property, which can be specified on the command line, via `-D`, or in a configuration file. A value set in code replaces the one from the command line, which in turn replaces the one from the configuration file.

There are two kinds of property names.

* Values concerning the deployment, the database, the server and how the client connects to it, have property names starting with `codion.`, such as `codion.db.url` and `codion.client.connectionType`. These are typically specified on the command line or in a configuration file, and the documentation refers to them by property name.
* All other values are named after the class containing them, by convention the fully qualified class name followed by the name of the constant in camel case, the property name of {url-javadoc}{framework-model}/is/codion/framework/model/EntitySearchModel.html#WILDCARD_PREFIX[EntitySearchModel.WILDCARD_PREFIX] being `is.codion.framework.model.EntitySearchModel.wildcardPrefix`. A few names differ from the convention, *PropertyValue.name()* returns the exact one.

=== Configuration file

The configuration file is a property file, specified via the `codion.configurationFile` system property, prefixed with `classpath:` in case it is located on the classpath, in which case it must be in the classpath root. No configuration file is loaded unless one is specified. A missing configuration file is not an error unless `codion.configurationFileRequired` is set to `true`, in which case a file must be specified as well.

==== Example configuration file

[source]
----
codion.client.connectionType=local
codion.db.url=jdbc:h2:mem:h2db
codion.db.initScripts=classpath:create_schema.sql
----
